## 二、GitHub Releases 正文 · 精简版（用户可读）

```
### v3.4.9 更新内容
1. 空闲期彻底停止测速 — 没有播放时只剩每小时一次的全端口扫描，而且只做连通性检查
   （HTTP 读 1 字节、RTSP 只到 PLAY 握手），不再读分片、不采样码率；播放关闭静默
   45 秒即停止深度探测，不再继续每 60 秒测速
2. 保存代理组不再清空池 — 只改某一组或静态 proxies 时，其它池的可用节点与整个端口段
   的测速历史（延迟/吞吐/失败次数/HTTP 状态）都会保留，不会全部变回「未测」
3. 测速失败状态会重置 — 每轮全端口扫描前清空失败计数与冷却；连续失败达到 3 次后改为
   每 2 分钟退避重试，出口恢复自动回列表，不必等 1 小时全扫或重启进程
4. 冷启动选路更稳 — 播放中的节点还没有吞吐样本时，用真实播放流量估算吞吐，
   不会再因为「延迟低但跑一会儿就卡」把坏节点选出来
5. 连通性扫描失败不再清空历史吞吐，节点恢复后仍按原吞吐排序

升级：下载对应平台压缩包解压覆盖后重启；Docker 用户重新拉取镜像；旧配置文件可直接使用。
Android 用户：App（APK）由独立仓库 qist/tvgate-android 按同一版本号发布；直接用二进制则下载
TVGate-android-*.zip。
```

## 三、完整版（用于发布公告 / 论坛 / 通知，用户可读）

```
## TVGate v3.4.9（2026-11-21）

本次修复代理池在「空闲仍测速」「保存配置清空池」「失败状态不重置」三处问题，
并补上冷启动的吞吐基线。配置格式向后兼容，可直接覆盖升级。

### 修复一：没有播放时不再测速

问题：
- 关闭播放后日志里仍每 60 秒出现「探测完成」，出口带宽被持续占用
- 全端口扫描（默认 1h）也在读完整分片、采样 RTP，空闲时同样产生测速流量

修复：
- 深度探测（读取完整分片、按后段速率算吞吐）严格只在组内有播放时运行
- 全端口扫描只做连通性检查：HTTP 读 1 字节、RTSP 只做到 PLAY 握手，
  不读分片、不采样码率，仅用于发现新端口
- 播放状态每 15 秒检查一次；最后请求后静默 45 秒即停止深度探测，
  不再按组的 interval（可能是 3 分钟）延迟

### 修复二：保存代理组不再清空池

问题：
- 在后台修改任意一个代理组（或只改静态 proxies），所有池的节点和测速数据都变回「未测」
- 日志里还会出现「移除已删除代理 pool-… 的运行状态」，看起来像池被删掉了

修复：
- 池配置未变化时，按新配置展开端口段并保留整个端口段的测速历史
  （延迟、吞吐、失败次数、HTTP 状态），只丢弃配置里真正删除的端口
- 池端口不再被当成「已删除代理」，热重载和后台保存后池保持原状，不重新测一轮

### 修复三：测速失败状态会重置

问题：
- 节点测速失败后一直停留在失败/冷却状态，出口恢复也要等下一次全量扫描或重启进程

修复：
- 每轮全端口扫描前清空所有候选的失败计数与冷却，扫描结果重新计数
- 连续失败达到 3 次后改为每 2 分钟退避重试；恢复后自动回到可用列表

### 选路改进

- 冷启动/刚重启时还没有吞吐样本，而播放中的节点又不额外采样，此前只能按延迟排序，
  容易再次选中「测速很快、跑一会儿就卡」的节点
- 现在播放中的节点没有样本时，用真实播放流量估算吞吐（30 秒窗口，不含探测流量）：
  出口真在传数据时数值与码率相当，停住时接近 0
- 「在用」窗口统一为 45 秒，播放停止后即可恢复完整采样

### 兼容性与升级

- 配置文件向后兼容：旧 config.yaml 可直接使用，无新增必填字段
- 二进制：下载对应平台压缩包，解压覆盖后重启服务（systemd：systemctl restart tvgate）
- Docker：docker pull juestnow/tvgate:v3.4.9（或 ghcr.io/qist/tvgate:v3.4.9），重建容器
- Android App（APK）：独立仓库 qist/tvgate-android 发布，版本号与服务端对齐，内嵌同版本服务端
- Android 二进制：Releases 页 TVGate-android-arm64-v8a.zip / TVGate-android-arm32-v7a.zip

### 发布校验

- 每个压缩包附 .dgst 校验文件（MD5/SHA1/SHA256/SHA512），下载后可比对
- 版本核对：./TVGate-linux-64 -version → v3.4.9
- 完整改动清单：doc/CHANGELOG.md
```
