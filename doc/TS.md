# TS 缓存（ts）

`ts` 段控制 TS（MPEG-TS 流媒体分片）的内存缓存。启用后，TVGate 会把已从上游拉取的 TS 分片缓存在内存中：同一频道的多个观众先后观看时，后到的请求直接命中缓存，无需再次回源拉取，显著减少对上游源站的重复请求和带宽占用——典型收益场景是"同一频道多观众"，热点频道的并发人数越多，回源次数越少。

缓存受两个参数约束：`cache_size` 限制缓存占用的总内存（MB），`cache_ttl` 控制分片在缓存中的存活时间，超期自动淘汰，保证观众拿到的仍是可用的最新分片。

## 工作方式

- 观众请求某个 TS 分片时，TVGate 先查内存缓存：**命中**则直接返回缓存数据，不回源；**未命中**才向上游源站拉取，拉取成功后写入缓存供后续观众复用。
- 缓存以 TS 分片为最小单位，同一分片只有第一次请求回源；不同观众请求同一频道的同一分片即可共享缓存。
- 缓存按 `cache_ttl` 淘汰过期分片，同时受 `cache_size` 总量上限约束，空间不足时淘汰旧分片，因此内存占用不会无限增长，也无需手动清理。
- 该缓存对组播转 HTTP（`/udp/...`）、HTTP/HTTPS 转发、H5 播放器等产生的 TS 分片请求同样生效，无需按频道单独配置。

## 配置段

```yaml
ts:
  enable: false       # 是否启用 TS 分片内存缓存，默认不启用
  cache_size: 128     # 缓存总大小上限（MB），默认 128
  cache_ttl: 2m       # 分片缓存存活时间（TTL），默认 2 分钟，超期自动淘汰
```

## 字段说明

三个字段均可省略，省略或取值非法时按默认值处理（`enable` 省略视为 `false`）。

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enable` | bool | `false` | 是否启用 TS 缓存；不配置或 `false` 时分片请求每次回源 |
| `cache_size` | int | `128` | 缓存总大小上限，单位 MB；配置 ≤0 时按默认 128 处理 |
| `cache_ttl` | duration | `2m` | 单个分片在缓存中的存活时间；配置 ≤0 时按默认 2 分钟处理 |

## 示例

服务器/家用 NAS（内存充裕，热点频道多）：

```yaml
ts:
  enable: true        # 开启 TS 缓存
  cache_size: 256     # 内存充裕时可调大到 256MB，容纳更多热点频道
  cache_ttl: 2m       # 保持默认 2 分钟，与常见 HLS 分片节奏匹配
```

路由器 / 安卓等小内存设备（OpenWrt、Termux 等）：

```yaml
ts:
  enable: true
  cache_size: 64      # 控制内存占用，只缓存最热的频道
  cache_ttl: 2m
```

## 注意事项

- **内存占用估算**：`cache_size` 是缓存可占用的内存上限（单位 MB），默认 128MB。实际占用与热点频道数量、码率、观众集中度相关；在路由器、安卓等小内存设备上建议保持默认或调小（如 `64`），服务器内存充裕时可调大提升命中率。
- **多观众场景收益最大**：缓存对"同一频道多观众"效果明显；观众都分散观看不同冷门频道时，命中率低，缓存收益有限。
- **TTL 不宜过长**：直播分片有时效性，`cache_ttl` 保持默认 2 分钟即可；调大可能让观众拿到过旧的分片导致播放异常。
- **默认关闭**：`enable` 不配置即为关闭，行为与旧版本一致（每次回源），升级后无需改动即可保持原行为。
- **缓存不持久化**：缓存位于内存，程序重启后清空，重启初期会出现短暂回源高峰，属正常现象。
- **观察效果**：开启后可通过 `monitor` 配置的状态接口（默认 `/status`）观察连接与流量变化，热点频道命中缓存时回源流量应明显下降。
- **热加载**：修改 `ts` 段后由配置热加载生效，无需重启程序。
