# Web 管理后台（web）

Web 管理后台为单页应用（SPA，随二进制嵌入），提供仪表盘监控、各模块可视化配置、代码文件管理、仓库同步编辑、日志与备份等管理能力。默认入口 `http://<IP>:<端口>/web/`，路径可由 `web.path` 自定义，所有后台页面与接口均在该前缀之下。

登录采用用户名 + 密码（登录 Cookie）；除此之外，敏感操作还需**二次输入登录密码**（独立短 TTL 授权 Cookie），进一步保护配置查看 / 保存与备份下载 / 恢复等高风险动作。登录页 `#/login` 公开访问、零鉴权请求；未认证访问后台接口返回 401，由前端内部跳转登录页。

## 配置段

```yaml
web:
  enabled: true      # 是否启用 Web 管理界面
  username: admin    # Web 管理用户名
  password: admin    # Web 管理密码；留空或仍是 admin 时，启动会自动换成随机口令（见下）
  path: /web/        # Web 管理路径（自定义）
```

## 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 是否启用 Web 管理界面 |
| `username` | string | 空 | Web 管理登录用户名 |
| `password` | string | 空 | Web 管理登录密码；二次授权（elevate）使用同一密码校验。**为空或等于 `admin` 时，启动会自动生成随机口令并写回配置** |
| `path` | string | `/web/` | 后台访问路径前缀，自定义后所有后台页面与 API 随之变化 |

## 示例

```yaml
web:
  enabled: true
  username: admin
  password: "change-me-to-a-strong-password"
  path: /web/
```

登录入口：`http://192.0.2.10:8888/web/`；代码文件管理器：`http://192.0.2.10:8888/web/code`；仓库同步编辑器：`http://192.0.2.10:8888/web/sync-editor`；配置备份中心：`http://192.0.2.10:8888/web/config/backup`。以上 `/web/` 为**未初始化时**的默认路径，路径一旦被随机化（见「初始凭据」），请把 `/web/` 换成实际 `web.path`。

## 注意事项

### 登录与访问控制

- 登录页 `#/login` 公开访问、零鉴权请求；未认证访问后台接口返回 `401`，由前端内部跳转登录页
- 所有代码文件接口均需登录 Cookie（cookieAuth），写操作限制在 docroot 内，防止 `../` 目录穿越

### 登录失败限流（防暴力破解）

登录与二次授权（elevate）的密码校验都按客户端 IP 计数：

- 同一 IP 在 5 分钟内失败 **5 次**后锁定 **5 分钟**，期间返回 `429 Too Many Requests`（带 `Retry-After` 与剩余秒数），登录页直接显示提示
- 认证成功后立即清零该 IP 的失败计数；不同 IP、不同接口（`login` / `elevate`）互不影响
- 计数保存在内存，进程重启后清零；只按 IP 不按用户名，避免攻击者故意失败把管理员账号锁死
- 客户端 IP 取 `RemoteAddr`；**仅当直连对端是回环地址**（同机 Nginx 反代）时才信任 `X-Real-IP` / `X-Forwarded-For`，防止伪造请求头绕过限流或陷害其他 IP
- 触发锁定会写审计日志：`🔒 [web] login 连续失败 5 次，已锁定 5m0s（IP 1.2.3.4，用户 "admin"）`

### 初始凭据（默认口令时随机化用户名 / 路径 / 口令）

启动（含首次启动与热重载）时**只看 `web.password`**：

- 口令已是自定义值 → **什么都不改**，`username`、`path` 即使还是 `admin`、`/web/` 也原样保留（老部署的后台地址不会变）；
- 口令为空或仍是 `admin` → 做初始化：口令换成 16 位随机值，`username` 与 `path` **仅在它们本身仍是默认值时才**随机化（已自定义的保持不动）。

| 字段 | 默认值（公开） | 初始化时的随机化结果 |
|---|---|---|
| `username` | `admin` | `adm` + 10 位小写字母数字，如 `adme54b4r2ygs` |
| `path` | `/web/` | `/` + 12 位小写字母数字 + `/`，如 `/4ib32ek5yvn5/` |
| `password` | `admin` / 空 | 16 位随机口令（含大小写、数字与符号） |

初始化时还会：

- 三项**写回配置文件**（只替换 `web` 段对应节点，注释与其它字段保留），磁盘上不再有公开默认值；
- 写入 `<配置文件所在目录>/web-initial-password.txt`（权限 `0600`），内容含访问路径、用户名与口令；
- 控制台与日志醒目打印：

```
========================================================
🔐 后台安全初始化：检测到默认值，已随机化
   访问路径: /4ib32ek5yvn5/   （已随机化，旧地址将失效）
   用户名:   adme54b4r2ygs
   口令:     s6byd27FNRju2-26
   凭据文件: /etc/tvgate/web-initial-password.txt（权限 0600，含以上三项）
   登录后请立即在「服务 → Web 设置」修改为自己的密码
========================================================
```

取用方式：`cat <配置目录>/web-initial-password.txt`，Docker 下为 `docker exec <容器> cat /etc/tvgate/web-initial-password.txt`，或 `docker logs <容器> | grep -A8 后台安全初始化`。

**升级影响**：只有**口令仍是默认值/空**的部署会被初始化（后台地址/用户名/口令可能一起变，新值见日志与凭据文件）；已经改过口令的部署完全不受影响。

**Android 例外**：`GOOS=android`（APK 内嵌 `.so` 或独立二进制）**不做随机化**，保持公开默认值 `admin` / `admin` / `/web/`。原因：三方 APK 通常没有展示 `web-initial-password.txt` 的界面，随机化会让用户永远登不进后台。安全性由「弱口令锁写」兜底——不改密码时，写配置、代码管理、定时任务、升级、备份等高危操作全部被拒绝，首次登录后需先在「服务 → Web 设置」改密解锁。已经被随机化的旧安装（凭据文件仍在且用户从未登录改密）会在下次启动时自动回退到默认值并删除凭据文件；用户已改过密码的完全不动。

显式指定初始口令：环境变量 `TVGATE_ADMIN_PASSWORD`（至少 10 位、不能是 `admin` 或用户名，过弱会被忽略并回落到随机口令）。口令改为自定义值后，`web-initial-password.txt` 会在下次加载时自动删除；后台顶部「当前使用初始凭据」提示会保留到改密完成，改密后 30 秒内消失。

### 修改密码需要当前密码

`POST config/save-web` 在提交了**新密码**时必须同时提交 `old_password`（当前密码），校验失败返回 `403`：

- 防止会话 Cookie 被劫持（或浏览器被他人临时使用）后直接改密，把真正的管理员锁在外面；
- 旧密码校验同样受失败限流约束（5 次/5 分钟，scope = `chpasswd`），不能用来在线爆破；
- 前端「服务 → Web 设置」新增「当前密码」输入框，修改密码时必填；改密成功后前端自动清空两个输入框。

### 弱口令保护（弱密码锁定高危操作）

即使不再是公开默认值，用户自定义的弱口令（如 `12345678`、`qwerty123`）仍会把后台暴露给字典攻击，后台会实时判定口令强度：

判定为弱口令的条件（满足任一）：

- 密码仍是默认的 `admin`（大小写不敏感；正常流程下启动时已被替换，仅手工改配置才会命中）
- 密码与用户名相同
- 密码长度不足 8 位
- 密码命中常见弱口令表（`123456`、`password`、`qwerty`、`admin123`、`tvgate` 等）

弱口令期间**锁定**以下操作（接口返回 `403` 并写明原因，后台顶部常驻黄色提示条）：

- 保存整份 YAML 配置（`config/save`）与各模块配置保存（`config/save-*`）
- 修改 PHP 目录 / PHP 模块配置（`config/save-php`）
- 定时任务的增删改与立即执行（`api/tasks/*`）
- 代码文件管理（`api/code/*`）、实时日志（`api/logs/*`）
- 仓库同步（`api/sync/*`）、GitHub 升级与加速配置（`github/*`、`api/github/*`）
- 配置备份 / 备份中心（`config/backup/*`、`api/backup/*`）
- DNS 配置（`api/dns/*`）、端点测试（`config/test-endpoint`）

弱口令期间**仍然允许**：登录、退出、登录状态查询、`config/web` 读取与 `config/save-web`（改密码本身）、各模块配置的只读 GET。

修改密码入口：后台「服务 → Web 设置」（`#/web`）。新密码要求至少 8 位，且不能与用户名或默认密码相同，否则保存返回 `400`。修改成功后顶部的弱口令提示与锁定会自动解除（提示条 30 秒内消失）。

`GET config/web` 不再回传明文密码，只返回 `password_set`（是否已设置）与 `password_weak` / `password_weak_hint`；保存时密码留空表示保持原密码不变。

### 二次授权（elevate，敏感操作保护）

登录 Cookie 之外，**敏感操作还需二次输入登录密码**：校验通过后颁发独立短 TTL 授权 Cookie（默认 10 分钟，HttpOnly + SameSite=Strict）。敏感接口：

- 查看整份配置：`GET <webPath>config`（含「配置查看」页与 YAML 编辑器加载）
- 保存配置：`POST <webPath>config/save`
- 配置备份下载 / 恢复：`<webPath>config/backup/download`、`<webPath>config/backup/restore`（以及备份中心对应的 `api/backup/download`、`api/backup/restore`）

流程：

```
POST <webPath>api/v1/elevate   {"password": "<登录密码>"}   # 解锁，颁发 10 分钟授权 Cookie
GET  <webPath>api/v1/elevate                                 # 查询当前授权状态与 TTL
```

- 未二次授权访问敏感接口返回 `403` JSON（`{"code":403,"msg":"需要二次验证：请输入登录密码"}`），前端弹窗引导输入密码后自动重试
- 密码校验与登录一致（常量时间比较 + 空口令拒绝）
- Web 未启用或未配置密码时，二次验证自动豁免
- 备份列表 / 删除等非敏感操作仅要求登录态

### 代码文件管理器

登录后台后访问 `/web/code`，可直接在浏览器中对 `docroot`（默认相对路径 `www`，即 PHP 脚本目录）下的文件进行可视化操作，无需 SSH 登录服务器：

| 操作 | 说明 |
|---|---|
| 列目录 | 递归列出 `docroot` 下所有文件与子目录 |
| 新建 | 新建文件或目录（相对路径，如 `sub/test.php`）；**同名已存在时先返回 409，前端弹窗确认后才覆盖，覆盖前自动备份为 `.bak.<时间戳>`**；取消则不修改任何文件。文件创建/覆盖成功后自动切到所在目录并在编辑器打开（含聚焦），新建目录则停留在当前目录 |
| 编辑/保存 | 在线编辑并保存到磁盘（保存前自动备份为 `.bak.<时间戳>`） |
| 上传 | 多选上传文件到指定子目录，自动防路径穿越；**覆盖同名旧文件前自动备份为 `.bak.<时间戳>`**（响应 `backed_up` 列出） |
| 上传解压 | 上传 `.zip` 并按配套 `.zip.md5` 自动解压，或手动解压；解压覆盖已有文件前同样自动备份 |
| 下载 | 以附件形式下载文件 |
| 删除 | 删除文件或整个目录 |
| 语法检测 | 对 PHP 源码做纯文本级简单检测（无需 PHP 运行时） |

**多目录**：配置了 `php.allowed_roots` 后，页面左侧顶部会出现「根目录」下拉框，可在 `PHP docroot` 与各附加目录之间切换；所有接口通过 `?root=<索引>` 指定根目录（0 = docroot，1..n = allowed_roots），后端只接受已配置的索引，不接受任意绝对路径。未配置时只有一个根目录。

接口与细节：

- 上传：`POST <webPath>api/code/upload`，`multipart` 字段 `file`（可多选）+ 可选 `dir`（目标子目录，默认 docroot 根）
- **ZIP 自动解压**：上传完成后，后端自动扫描同目录下是否存在配对文件 `xxx.zip` 与 `xxx.zip.md5`；若 `.zip.md5` 内容第一个字段与 zip 的实际 MD5 一致，立即解压到同目录（**覆盖模式**）；没有 `.zip.md5` 不算错（zip 仅作为普通文件上传，不会自动解压）；MD5 不匹配或解压失败逐项回报在响应 `unzip` 数组，不中断整体上传
- 手动解压：`POST <webPath>api/code/unzip`，两种模式：① 指定磁盘已有 zip `?path=xxx.zip&dir=目标目录`（`dir` 省略则解压到 zip 所在目录）；② multipart 上传并解压，可选 `flatten=true` 展平子目录
- `.zip.md5` 生成示例（首字段为期望 MD5，后续字段如文件名会忽略）：

```
echo -n "$(md5sum xxx.zip | awk '{print $1}')" > xxx.zip.md5
```

- 语法检测（`simplePHPCheck`）：纯 Go、无 PHP 二进制前提下的文本级检查，可识别未以 `<?php` / `<?` 开始标签开头（warning）、括号 `()` `{}` `[]` 不匹配或未闭合（error）、单 / 双引号字符串未闭合与块注释 `/*` 未闭合（error）；为轻量静态检查，不能替代完整 PHP 解释器，真正执行仍由 phpgo 运行时完成
- 安全：解压统一含路径穿越防护（归档内 `../` 或绝对路径条目被丢弃）并约束在 docroot 内

### 三处备份机制

TVGate 在**配置、代码中心、同步中心**三处各自有"改前备份旧内容"的备份规则，均可回滚：

1. **config.yaml 配置备份**：通过 Web 后台保存任意配置时，各保存处理器在写回新配置前先把当前 `config.yaml` 完整复制为 `config.yaml.backup.<时间戳>`（时间戳格式 `20060102150405`），与配置文件同目录；每次保存新增一条、不覆盖旧备份，内容为明文。**配置备份中心**（`/web/config/backup`）对同目录所有 `*.backup.*` 文件提供列表 / 删除 / 批量删除 / 还原 / 下载（按时间从新到旧排序），无自动清理，需手动或定期清理；还原会把选中的备份写回 `config.yaml`。
2. **代码中心备份**：编辑器保存或批量替换前先把旧文件复制为 `原文件.bak.<时间戳>`（时间戳格式 `YYYY-MM-DD_HH-MM-SS`，与原文件同目录）再写入新内容；批量替换递归遍历文本文件，跳过 `.bak`、隐藏、超大（>5MB）、二进制（含 `\0`）文件。**备份文件管理中心**（入口在代码编辑页）统一管理 docroot 下所有 `.bak` 文件，支持列表 / 回滚（回滚前也会先备份当前文件，避免不可逆覆盖）/ 下载 / 单个与批量删除 / 自动清理（按原文件分组，每组保留最新 N 个，`keep` 可设 0=全删）。
3. **同步中心备份**：仓库同步在覆盖或删除本地文件前，若该条目 `backup: true`（默认 `true`），把将被覆盖 / 删除的本地文件备份为 `.bak.<时间戳>`（时间戳格式 `20060102-150405`）；`protect` 保护清单中的文件永不覆盖、永不删除；孤立文件报告会跳过 `.bak` 备份文件，避免误报。
