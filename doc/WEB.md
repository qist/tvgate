# Web 管理后台（web）

Web 管理后台为单页应用（SPA，随二进制嵌入），提供仪表盘监控、各模块可视化配置、代码文件管理、仓库同步编辑、日志与备份等管理能力。默认入口 `http://<IP>:<端口>/web/`，路径可由 `web.path` 自定义，所有后台页面与接口均在该前缀之下。

登录采用用户名 + 密码（登录 Cookie）；除此之外，敏感操作还需**二次输入登录密码**（独立短 TTL 授权 Cookie），进一步保护配置查看 / 保存与备份下载 / 恢复等高风险动作。登录页 `#/login` 公开访问、零鉴权请求；未认证访问后台接口返回 401，由前端内部跳转登录页。

## 配置段

```yaml
web:
  enabled: true      # 是否启用 Web 管理界面
  username: admin    # Web 管理用户名
  password: admin    # Web 管理密码（敏感操作二次授权使用同一密码）
  path: /web/        # Web 管理路径（自定义）
```

## 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 是否启用 Web 管理界面 |
| `username` | string | 空 | Web 管理登录用户名 |
| `password` | string | 空 | Web 管理登录密码；二次授权（elevate）使用同一密码校验 |
| `path` | string | `/web/` | 后台访问路径前缀，自定义后所有后台页面与 API 随之变化 |

## 示例

```yaml
web:
  enabled: true
  username: admin
  password: "change-me-to-a-strong-password"
  path: /web/
```

登录入口：`http://192.0.2.10:8888/web/`；代码文件管理器：`http://192.0.2.10:8888/web/code`；仓库同步编辑器：`http://192.0.2.10:8888/web/sync-editor`；配置备份中心：`http://192.0.2.10:8888/web/config/backup`。

## 注意事项

### 登录与访问控制

- 登录页 `#/login` 公开访问、零鉴权请求；未认证访问后台接口返回 `401`，由前端内部跳转登录页
- 所有代码文件接口均需登录 Cookie（cookieAuth），写操作限制在 docroot 内，防止 `../` 目录穿越

### 模块一览

| 分类 | 页面 |
|---|---|
| 概览 | 仪表盘（版本/系统/CPU/内存/连接/资源/网络/应用进程） |
| 配置 | 定时任务、代理组、视频解析（jx）、推流发布、域名映射、播放器、全局认证、组播配置、TS 缓存、配置查看 |
| 服务 | 服务器、HTTP、DNS、PHP 模块、重载、Web 设置、日志配置 |
| 内容 | 代码文件管理、仓库同步、GitHub 加速 |
| 运维 | 实时日志、配置备份、备份中心 |
| 工具 | YAML 编辑器 |

### 二次授权（elevate，敏感操作保护）

登录 Cookie 之外，**敏感操作还需二次输入登录密码**：校验通过后颁发独立短 TTL 授权 Cookie（默认 10 分钟，HttpOnly + SameSite=Strict）。敏感接口：

- 查看整份配置：`GET <webPath>config`（含「配置查看」页与 YAML 编辑器加载）
- 保存配置：`POST <webPath>config/save`
- 配置备份下载 / 恢复：`<webPath>config/backup/download`、`<webPath>config/backup/restore`（以及备份中心对应的 `api/backup/download`、`api/backup/restore`）

流程：

```
POST <webPath>api/v1/elevate   {"password": "<登录密码>"}   # 解锁，颁发 10 分钟授权 Cookie
GET  <webPath>api/v1/elevate                                 # 查询当前授权状态与 TTL
```

- 未二次授权访问敏感接口返回 `403` JSON（`{"code":403,"msg":"需要二次验证：请输入登录密码"}`），前端弹窗引导输入密码后自动重试
- 密码校验与登录一致（常量时间比较 + 空口令拒绝）
- Web 未启用或未配置密码时，二次验证自动豁免
- 备份列表 / 删除等非敏感操作仅要求登录态

### 代码文件管理器

登录后台后访问 `/web/code`，可直接在浏览器中对 `docroot`（默认相对路径 `www`，即 PHP 脚本目录）下的文件进行可视化操作，无需 SSH 登录服务器：

| 操作 | 说明 |
|---|---|
| 列目录 | 递归列出 `docroot` 下所有文件与子目录 |
| 新建 | 新建文件或目录（相对路径，如 `sub/test.php`） |
| 编辑/保存 | 在线编辑并保存到磁盘（保存前自动备份为 `.bak.<时间戳>`） |
| 上传 | 多选上传文件到指定子目录，自动防路径穿越 |
| 上传解压 | 上传 `.zip` 并按配套 `.zip.md5` 自动解压，或手动解压 |
| 下载 | 以附件形式下载文件 |
| 删除 | 删除文件或整个目录 |
| 语法检测 | 对 PHP 源码做纯文本级简单检测（无需 PHP 运行时） |

接口与细节：

- 上传：`POST <webPath>api/code/upload`，`multipart` 字段 `file`（可多选）+ 可选 `dir`（目标子目录，默认 docroot 根）
- **ZIP 自动解压**：上传完成后，后端自动扫描同目录下是否存在配对文件 `xxx.zip` 与 `xxx.zip.md5`；若 `.zip.md5` 内容第一个字段与 zip 的实际 MD5 一致，立即解压到同目录（**覆盖模式**）；没有 `.zip.md5` 不算错（zip 仅作为普通文件上传，不会自动解压）；MD5 不匹配或解压失败逐项回报在响应 `unzip` 数组，不中断整体上传
- 手动解压：`POST <webPath>api/code/unzip`，两种模式：① 指定磁盘已有 zip `?path=xxx.zip&dir=目标目录`（`dir` 省略则解压到 zip 所在目录）；② multipart 上传并解压，可选 `flatten=true` 展平子目录
- `.zip.md5` 生成示例（首字段为期望 MD5，后续字段如文件名会忽略）：

```
echo -n "$(md5sum xxx.zip | awk '{print $1}')" > xxx.zip.md5
```

- 语法检测（`simplePHPCheck`）：纯 Go、无 PHP 二进制前提下的文本级检查，可识别未以 `<?php` / `<?` 开始标签开头（warning）、括号 `()` `{}` `[]` 不匹配或未闭合（error）、单 / 双引号字符串未闭合与块注释 `/*` 未闭合（error）；为轻量静态检查，不能替代完整 PHP 解释器，真正执行仍由 phpgo 运行时完成
- 安全：解压统一含路径穿越防护（归档内 `../` 或绝对路径条目被丢弃）并约束在 docroot 内

### 三处备份机制

TVGate 在**配置、代码中心、同步中心**三处各自有"改前备份旧内容"的备份规则，均可回滚：

1. **config.yaml 配置备份**：通过 Web 后台保存任意配置时，各保存处理器在写回新配置前先把当前 `config.yaml` 完整复制为 `config.yaml.backup.<时间戳>`（时间戳格式 `20060102150405`），与配置文件同目录；每次保存新增一条、不覆盖旧备份，内容为明文。**配置备份中心**（`/web/config/backup`）对同目录所有 `*.backup.*` 文件提供列表 / 删除 / 批量删除 / 还原 / 下载（按时间从新到旧排序），无自动清理，需手动或定期清理；还原会把选中的备份写回 `config.yaml`。
2. **代码中心备份**：编辑器保存或批量替换前先把旧文件复制为 `原文件.bak.<时间戳>`（时间戳格式 `YYYY-MM-DD_HH-MM-SS`，与原文件同目录）再写入新内容；批量替换递归遍历文本文件，跳过 `.bak`、隐藏、超大（>5MB）、二进制（含 `\0`）文件。**备份文件管理中心**（入口在代码编辑页）统一管理 docroot 下所有 `.bak` 文件，支持列表 / 回滚（回滚前也会先备份当前文件，避免不可逆覆盖）/ 下载 / 单个与批量删除 / 自动清理（按原文件分组，每组保留最新 N 个，`keep` 可设 0=全删）。
3. **同步中心备份**：仓库同步在覆盖或删除本地文件前，若该条目 `backup: true`（默认 `true`），把将被覆盖 / 删除的本地文件备份为 `.bak.<时间戳>`（时间戳格式 `20060102-150405`）；`protect` 保护清单中的文件永不覆盖、永不删除；孤立文件报告会跳过 `.bak` 备份文件，避免误报。
