## 二、商店更新说明 · 标准版（≤ 800 字符）

```
【v3.3.8 更新内容】
1. 组播 4K 花屏/蓝屏修复 — 4K 等组播频道此前会周期性花屏、严重时整屏蓝屏，
   根因是下发给播放器的画面数据块被复用了下一包的内存，导致同一段数据被重复
   下发；现已改为独立副本，并加速下发路径（4K 卡顿同时改善）
2. 长时间运行更稳 — 修复反复换台、多设备进出后内部对象残留（内存与连接不再
   持续增长）；旧版组播网卡配置自动迁移，升级后部分频道不再 0 字节/绿屏
3. 订阅内联代理（新增）— 订阅文件里可直接给频道指定上游代理与
   Referer/Origin（proxy= / referer= / origin=），无需先建代理组；
   支持 socks5 / socks4 / http(s)，多代理自动挑最快，跳转与分片全程同一出口
4. 播放页换台观感修复 — 过渡期旧频道画面+声音继续播放，新频道接上的那一刻
   才切换（此前点一下换台就停播、等下一个节目起播）；控制条恢复整幅铺满

提示：本版本同时更新了内嵌服务端，建议使用同一版本的 App 与 Web 管理后台。
```

## 三、商店更新说明 · 详细版（无字数限制，用于官网 / 论坛 / Release Notes）

```
## v3.3.8（2026-10-03）

### 本次亮点
- 修掉组播（IPTV 组播源）4K / 高码率频道周期性花屏、蓝屏，4K 卡顿一并改善
- 新增订阅内联代理：订阅文件里就能给频道写代理与请求头，无需建代理组规则
- 修掉播放页「一点换台就停播、等下一个节目起播」的观感回归

### 修复与改进
- 组播花屏 / 蓝屏根因修复：
  - 现象：4K 组播频道周期性花屏，严重时整屏蓝屏；普通高清频道不易复现
  - 根因：下发给播放器的画面数据块复用了会被下一个网络包覆盖的内存，
    导致同一段画面数据被重复下发
  - 修复：读入与下发都改为按实际长度的独立副本，并补回归测试
- 组播卡顿与稳定性：
  - 下发路径回归「每包即时直写」，出图更及时、高码率卡顿明显减少
  - RTP 去重窗口加大并全量比对，弱网 / 乱序下更少误判丢帧
  - TS 连续性补齐对齐旧版行为，兼容旧播放器与 4K 解码路径
  - 修复客户端加入/移除竞态导致的内部对象残留（反复换台、多设备进出后
    内存与 UDP socket 不再持续增长）
- 旧版组播网卡配置自动迁移：沿用旧配置的用户升级后，部分组播频道不再
  出现 0 字节 / 绿屏，无需手工改配置
- 订阅内联代理与请求头（新增）：
  - 订阅（TXT）新增 proxy= / referer= / origin= 行，支持组级默认与频道级
    覆盖；M3U 订阅支持同名属性
  - 支持 socks5 / socks4 / socks4a / http / https（可带 user:pass@）
  - 多个代理自动挑选最快；302 跳转与后续分片全程走同一出口
  - 未配置即回落原有代理组 / 直连，直播、回看、点播一致生效
- 播放页无感换台回归修复：过渡期旧频道画面+声音照常播放，新频道在后台
  静默起播，真正接上的那一刻画面与声音一起切换；换流遮罩只在硬切/
  无缝失败回退时出现；控制条恢复整幅铺满

### 说明
- 支持 Android 5.0 及以上；arm64-v8a / armeabi-v7a / x86_64
- 内嵌服务端同步至 v3.3.8；建议 App 与 Web 管理后台使用同一版本
- 完整改动见 doc/CHANGELOG.md（Android 与 服务端 两段）
```
