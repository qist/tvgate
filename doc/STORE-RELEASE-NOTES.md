## 二、商店更新说明 · 标准版（≤ 800 字符）

```
【v3.4.8 更新内容】
1. 代理池吞吐探测重做 — 改为读取完整直播分片，吞吐按最后 3 秒的速率计算；
   能识别「前 3 秒跑满 7Mbps、随后限速到 2Mbps 甚至停住」的出口。此前只读 2MB，
   正好停在突发段，会把实际跑不动的节点测成最快并持续选中，导致画面反复卡顿
2. 探测与重试 — HTTP 探测超时下限提高到 8s（默认 10s）；RTSP 组补充 2s 码率采样；
   分片没读到数据时保留上次结果，探测失败一次也会在下一轮自动重试
3. 选路更稳 — 优先选择吞吐最大的节点，首包稍慢但带宽足够的节点不再被直接排除
4. 探测节奏简化 — 深度探测仅在播放时运行，全端口扫描默认每小时一次，空闲时探测流量更低
5. 后台代理组页 — 增加「吞吐」「HTTP」列，负载均衡改为下拉，修复编辑输入卡顿
6. App 前端无改动 — 本次仅随内嵌服务端重新打包，覆盖安装即可升级
```

## 三、商店更新说明 · 详细版（无字数限制，用于官网 / 论坛 / Release Notes）

```
## v3.4.8（2026-11-21）

### 本次亮点
- 内嵌服务端同步至 v3.4.8：代理池吞吐探测重做，选路更准，播放更稳
- 后台代理组页增加吞吐显示，修复编辑卡顿
- App 前端无改动，覆盖安装即可升级

### 问题与修复
- 现象：代理池某个节点测速能到 6~7Mbps，被选为最快，但实际播放 5MB 分片要十几秒，
  播放器反复断开
- 原因：这类出口「前 3 秒突发、随后限速甚至停住」，旧探测只读 2MB，正好停在突发段，
  测出的值远高于持续带宽
- 修复：读取完整分片，吞吐只看最后 3 秒；后段没有数据记 0；HTTP 探测超时下限提高到 8s；
  RTSP 组补充 2s 码率采样；无有效样本时保留上次结果，失败节点自动重试

### 其他
- 深度探测仅在组内有播放时运行，全端口扫描按小时执行，空闲时几乎不产生探测流量
- 后台节点表增加「吞吐」「HTTP」列，负载均衡改为下拉
- 修复 RTSP→HTTP 流结束时的响应头告警，减少日志刷屏

### 说明
- 支持 Android 5.0 及以上；arm64-v8a / armeabi-v7a / x86_64
- 内嵌服务端同步至 v3.4.8（versionCode 以 tvgate-android 仓库为准，可覆盖安装升级）
- 配置格式向后兼容，旧 config.yaml 可直接使用
- 完整改动见 doc/CHANGELOG.md（Android 与 服务端 两段）
```
