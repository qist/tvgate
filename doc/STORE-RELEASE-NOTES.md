## 二、商店更新说明 · 标准版（≤ 800 字符）

```
【v3.4.9 更新内容】
1. 空闲期停止测速 — 没有播放时只剩每小时一次的全端口扫描，且只做连通性检查
   （HTTP 读 1 字节、RTSP 只到 PLAY 握手），不读分片、不采样码率；播放关闭后
   静默 45 秒即停止深度探测，不会继续每 60 秒测速
2. 保存配置不再清空池 — 只修改某一组或静态代理时，其它代理池的可用节点与整个
   端口段的测速历史（延迟/吞吐/失败次数/HTTP 状态）都会保留
3. 失败状态自动重置 — 每轮全端口扫描前清空失败计数与冷却；连续失败达到 3 次后
   改为每 2 分钟退避重试，出口恢复自动回列表，不必等 1 小时或重启进程
4. 冷启动选路更稳 — 播放中的节点缺少吞吐样本时，用真实播放流量估算，
   不再因「延迟低但跑一会儿就卡」选中坏节点
5. App 前端无改动 — 本次仅随内嵌服务端重新打包，覆盖安装即可升级
```

## 三、商店更新说明 · 详细版（无字数限制，用于官网 / 论坛 / Release Notes）

```
## v3.4.9（2026-11-21）

### 本次亮点
- 内嵌服务端同步至 v3.4.9：空闲期停止测速、保存配置不再清空代理池、失败状态自动重置
- App 前端无改动，覆盖安装即可升级

### 问题与修复
- 现象一：关闭播放后日志仍每 60 秒出现「探测完成」，空闲时也在消耗出口带宽
  修复：深度探测只在有播放时运行；全端口扫描改为仅连通性检查（1 字节 / RTSP 握手）；
        播放关闭静默 45 秒即停止，不再按组的 interval 延迟
- 现象二：后台修改任意一组代理配置，所有池的节点和测速数据都变回「未测」
  修复：池配置未变化时保留整个端口段的测速历史；池端口不再被误判为「已删除代理」
- 现象三：测速失败后节点长期停留在失败/冷却状态，出口恢复也要重启进程
  修复：每轮全端口扫描前清空失败计数与冷却；失败 3 次后按 2 分钟退避重试
- 现象四：重启后没有吞吐样本，只能按延迟排序，又选中「跑一会儿就卡」的节点
  修复：播放中的节点用真实播放流量估算吞吐（30 秒窗口，不含探测流量）

### 说明
- 支持 Android 5.0 及以上；arm64-v8a / armeabi-v7a / x86_64
- 内嵌服务端同步至 v3.4.9（versionCode 17，可覆盖安装升级）
- 配置格式向后兼容，旧 config.yaml 可直接使用
- 完整改动见 doc/CHANGELOG.md（Android 与 服务端 两段）
```
